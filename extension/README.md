# Kult Player Bridge

Тестовое Chrome-расширение для проверки доступа к `<video>` во вложенных iframe.

## Установка

1. Открыть `chrome://extensions`.
2. Включить **Режим разработчика**.
3. Нажать **Загрузить распакованное расширение**.
4. Выбрать папку `extension`.

## Проверка

1. Открыть `index.html` в Chrome.
2. Дождаться загрузки страницы и видеоплеера.
3. Нажать на значок расширения.
4. Нажать **Подключить плеер** и подтвердить доступ к обнаруженным доменам.
5. Если статус показывает подключённый плеер, используйте его обычные кнопки **Play**, **Pause** и перемотки.

После первого предоставления доступа повторно подключаться не нужно. Chrome сохраняет разрешения на домены, а popup при каждом открытии заново находит актуальные iframe и автоматически восстанавливает связь с плеером. Кнопка разрешения появится снова только при обнаружении нового домена.

Расширение отслеживает реальные события элемента `<video>`, возникающие после использования штатных кнопок плеера. Последнее обнаруженное событие отображается в popup.

Расширение работает только на `http://194.226.165.6:8787/`. Доступ к известным доменам плеера `bulkikim.lol` и `theatre.stravers.live` объявлен заранее; посторонние iframe, включая рекламные и служебные Google-фреймы, игнорируются.

События плеера пересылаются только тогда, когда верхняя вкладка открыта на `http://194.226.165.6:8787/`. Badge `ON` означает готовый плеер, `…` — загрузку, `!` — необходимость однократной активации видео пользователем.

Если Chrome не показывает вложенные фреймы для страницы, открытой через `file://`, запустите `index.html` через локальный HTTP-сервер (например, Live Server в редакторе).

## Что проверяет прототип

- можно ли внедрить скрипт в домен внешнего плеера;
- существует ли в нём стандартный элемент `<video>`;
- разрешает ли браузер вызвать `video.play()` и `video.pause()`;
- меняется ли домен плеера при выборе другого источника.
- приходят ли события `play`, `pause`, `seeked` и `ratechange` от штатного плеера.

Сайт комнаты передаёт локальные события плеера на WebSocket-сервер. Команды других участников возвращаются через service worker в нужный iframe и применяются без обратной отправки события.
